> 整理日期：2026-10-27。状态：维护方法。从历史执行包提炼步骤，不恢复旧调用预算，不宣称本轮完成真实联调。

## 使用前确认范围

适用于已有的知识库、上传、问答、来源、历史和反馈主路径。新能力与验收范围以[活动任务](../../.ai/ACTIVE_TASK.md)和对应 change 为准。客户端合成测试、布局验证和真实 provider 闭环分别报告。

已接受范围见[前端收口](../90-历史归档/2026-10_前端Demo接入/阶段收口.md)，欠缺证据见[技术债](../01-规划与调研/技术债与证据缺口.md)。

## 复核顺序

1. 核对当前代码、活动任务和已有数据，隔离专用测试目标，保留原容器与数据卷。
2. 从仓库根目录执行现有只读预检；端口监听不能代替业务健康或执行授权：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/frontend_live_preflight.ps1 -Json
   ```

3. 核对实际 endpoint、模型、向量维度、分块、查询变体、retry/timeout、Router 与 rerank；不沿用旧执行包的模型名称和调用上限。
4. 写入、上传或真实问答前，按 [AGENTS.md](../../AGENTS.md)披露目标、数据出站、调用量、模型、费用与失败副作用，并取得覆盖本次范围的授权。
5. 运行获准的最小闭环，保存同次响应、终态、来源和历史/反馈读回。上传应返回接受状态和非空 taskId；接受不明时查原任务，不盲目重发。
6. 同步与结构化流式分开报告。流式来源取自同次有效 ANSWER terminal；停止接收不证明服务端已取消。客户端本页过滤不是全量搜索，单条历史不是多轮会话。
7. 核对持久化、权限和清理证据；仅按授权清理明确的专用目标。保留失败和未完成记录，一次成功不证明长期稳定性。

当时的完整语境见[历史执行包](../90-历史归档/2026-10_前端Demo接入/真实闭环执行包-历史快照.md)与[原始预检](../90-历史归档/2026-10_前端Demo接入/真实闭环预检-2026-10-17.json)。它们只用于复盘，不是当前环境事实或新增授权。
