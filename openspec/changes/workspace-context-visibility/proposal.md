# 工作空间归属与可见范围正式接入

## 为什么改

用户无法在前端看清当前组织，“公开／私有”也容易被误解；刷新页面还会丢失内存用户资料。新增当前账号上下文读取，在现有侧栏与个人资料展示真实归属，并补全状态。

## 范围与授权

2026-10-27 用户先确认[规划范围](../../../docs/01-规划与调研/工作空间归属与可见范围-设计规划.md)，随后要求使用 landing-page-design 的信息层级与状态补全辅助实现；另行确认轨迹任务已验收。本轮据此正式接入，提交、push、部署、本 change 接受/归档均未授权。

- 新增只读 GET /api/session/context，从服务端 userId/tenantId 读取有效账号与组织。
- 完成前端共享状态、刷新恢复、轮换重读、失败重试、迟到响应与身份变化处理。
- 在既有侧栏/折叠/移动入口和个人资料显示归属，统一知识库可见范围文案。
- 保留既有字体、主题、Lucide、聊天输入与轨迹；无新增依赖、数据列或基础设施。

`confirmed`：服务端身份、租户内授权、共享 refresh 与会话序号。`partial`：隔离有合成证据，不等于生产多租户 SLA。`planned`：本 change 的接口和 UI。`unknown`：真实数据库名称与运行环境。`out_of_scope`：租户 CRUD/切换、成员管理、计费、配额、新角色、检索和生成协议变更。

## 验证、成本与风险

按 [design](design.md)、[tasks](tasks.md) 与 [规格](specs/rag-system/spec.md) 连续实现。验证 SQL 双组织/身份状态、HTTP 契约、前端竞态和组件状态、全量前端测试及包含 vue-tsc 的 build、相称 Maven、DocAndScope/SensitiveLogs。浏览器不可用则明确跳过。

真实 ask/embedding/rerank/judge/provider 预算 0，不访问真实数据库或敏感配置。主要风险是上下文自身触发 refresh 时的竞态、旧账号响应回填，以及老后端没有新接口时的失败显示；不得编造名称或退回默认租户。
