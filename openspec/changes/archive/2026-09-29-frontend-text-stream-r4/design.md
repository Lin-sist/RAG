# R4 设计

## 实现

`useSSE` 作为唯一流解析入口，按 SSE 空行组成事件，跨网络帧保留 UTF-8 和未完结行；`[ERROR]` 优先于后续 `[DONE]`，AbortController 中断单独标记。聊天页仅消费纯文本 chunk 与本地 transport 状态。同步问答保持默认；历史详情仍只读。

## 验证

合成用例覆盖分帧、前导空格、多行事件、尾部、`[ERROR]` 后 `[DONE]`、无 `[DONE]` 断流和 abort；正式 build 包含 `vue-tsc`。真实联调仅用用户授权的 KB17 一次纯文本流。

## 决策记录

### 决策 1：正式聊天页如何开放文本流
- **面临的选择**：默认替换同步问答；保留同步默认并显式切换文本流。
- **选了哪个 + 为什么**：保留同步默认并显式切换，现有同步来源展示已验收，流接口只提供文本。
- **放弃的代价**：默认替换会让用户失去当前可展示的来源，并误以为流式答案同样有引用。

### 决策 2：如何解析流事件
- **面临的选择**：聊天页自己切行；统一在现有 `useSSE` 中解析完整 SSE 事件。
- **选了哪个 + 为什么**：统一在 `useSSE` 中解析，正式页和旧页可共用，网络分帧不泄漏到展示层。
- **放弃的代价**：聊天页自己解析会产生第二套协议逻辑，错误和中断容易再次分叉。

### 决策 3：流结束如何表述
- **面临的选择**：把 `[DONE]` 当业务回答成功；只标记纯文本传输结束或异常。
- **选了哪个 + 为什么**：只标记传输结果，当前 wire 没有结构化 final state、引用和服务端取消确认。
- **放弃的代价**：宣称业务成功会把拒答、错误或未验证引用误报成有效回答。

### 决策 4：本轮不补流式来源和服务端取消
- **面临的选择**：补一次同步 ask 获得来源并称已停止生成；只显示流接口已提供的文本并注明客户端停止接收。
- **选了哪个 + 为什么**：只使用流接口事实，避免额外 provider 调用和未经 C21 定义的终态语义。
- **放弃的代价**：补同步 ask 会产生第二条问答及 history，客户端 abort 也不能证明服务端停止。
