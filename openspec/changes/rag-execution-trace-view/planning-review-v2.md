## 本地交互设计稿已观察到的行为

| 检查 | 实际结果与边界 |
| --- | --- |
| 正反拖选 | 同一屏幕端点分别正/反拖动后，两个 slider 均为 986–3080 ms，匹配 1 个助手操作；这些是模拟轨迹的原型结果 |
| 平移 | 选区从 986–3080 ms 平移为 1762–3856 ms，跨度保持约 2.09 s |
| 端点与键盘 | 左端拖为 1452 ms，右端 Shift+Right 从 3856 改为 4338 ms，原始操作时间不变 |
| 筛选交集 | 范围内筛上下文为 0 项；清除时间范围后仍保留上下文筛选；再筛检索阶段为 0，恢复全部阶段后为 1 |
| 分类详情 | 工具参数只显示 rag.rerank 与保留上限；助手有回答/计时且未提供首 Token 时明确缺失；上下文来源有模拟的两份授权来源 |
| 深浅与响应式 | 浏览器已查看深/浅主题；实际 CSS 1440×900 时内容宽 1128，右侧详情为 sticky；CSS 390×844 时页面 scrollWidth=390、详情为 fixed/dialog |
| 焦点与输入 | Escape 关闭窄屏详情后焦点回到对应操作按钮；对话/轨迹切换后未发送草稿仍保留 |
| 运行隔离 | 设计 HTML 无外部脚本/字体/接口，CSP connect-src none，发送按钮禁用；仅本机静态预览读取，没有真实 ask/provider |

原型拖选中发现列表筛短后滚动条消失会改变时间轴宽度，现用稳定滚动条占位及一次拖动内固定坐标基准解决；正反拖选复查端点一致。此修复只在隔离设计稿内，不声称正式前端已有相关实现。
