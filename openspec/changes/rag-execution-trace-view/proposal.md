# 单次问答轨迹：把执行过程变成安静、可检查的时间线

## 为什么改

正式聊天页能展示回答、来源和流式终态，但用户仍不知道时间花在哪里、实际执行了哪些步骤，以及降级时发生了什么。旧静态 Demo 的检索步骤和可观测页面使用演示数据，不能代表真实问答轨迹。

用户希望借鉴 DeepSeek Harness 的时间总览和轨迹入口，同时减少密集文字。2026-10-27 进一步要求至少三色区分、简短调用说明、分类操作详情与滑动选区，并授权调研已打开的应用。本轮实际观察与设计取舍见[调研记录](harness-research-v2.md)，不声称复现其内部协议。

## 目标与范围

- 在现有 ChatPanel 内提供“对话 / 轨迹”切换，保留侧栏、主题、输入框和当前回答状态。
- 以琥珀色工具、紫色助手、青绿色上下文三轨总览表达真实活动；列表每项增加一句说明，点击条或行打开对应详情。
- 支持拖选时间范围、调整边界、区间平移和键盘替代；四阶段保留作本页筛选，所有操作均可检查。
- 规划同步问答最终快照，以及流式问答经显式协商传递的阶段事件。首版覆盖当前页面内的单次问答，不新增轨迹查询服务或数据库。
- 轨迹来自真实生命周期。缓存命中、无答案、降级、失败和连接中断均有明确呈现，缺失数据不补造。
- 保留 OpenSpec 设计、第二版视觉稿及零网络交互稿；用户确认第二版后，本轮继续完成正式组件与同步/流式数据接线。

## 风险

2026-10-27 后续授权：用户认可第二版，要求规划并接入正式聊天页，并明确“现有正式前端输入框样式不变”。本轮据此实施已确认的轨迹设计与数据接线；设计稿的 composer、侧栏和占位内容不迁入正式页面。真实业务调用预算仍为 0，不自动提交或接受/归档。

同日再次授权：用户要求把同步/流式两个常驻按钮收进输入框高级选项，按既有能力内的 Type B 局部维护执行；仅该入口不再冻结原模板/CSS，其余问答契约与授权边界沿用现状。

同日最新授权进一步覆盖现有输入区的整体 Demo 样式对齐及菜单遮挡修复；复用正式已接通入口，不新增语音、照片等占位能力，不改变问答协议或扩展外部调用预算。

阶段分组可能隐藏细节，因此详情保留真实子阶段与时间。未协商就向现有流塞入新事件会触发协议错误，因此保留原 structured-v1 行为。采集失败只影响轨迹可用性，不改变问答结果或历史规则，详见设计 D2–D5。
