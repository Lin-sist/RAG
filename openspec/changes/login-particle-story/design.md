# 登录页粒子故事 · 四幕设计与第三轮精修

## 💡 30秒人话设计主旨

第一轮已经让文档、检索和回答可以随滚轮变形，但散开时像把粒子撒进一个方盒子，左侧文字也一直不变。第二轮先让粒子组成项目自己的双翼 Logo，再依次讲“资料、线索、答案”的故事。散开的粒子围绕图样形成疏密自然的轮廓，随后收紧细节；左侧标题与说明同步切换，下面的登录表单一直留在原位。

第三轮让金色翼尖贴住白色下翼，清空图样下方的文字和选项，只留下暂停图标；同时放大图样，让右侧留白更合适。点击图样或使用局部键盘操作仍可查看全部四幕。

本文件包含用户于 2026-10-26 回复“开始实现”后确认的第二轮设计，以及随后直接要求的第三轮微调。实现进度以 tasks.md 为准；首轮验证见 [acceptance.md](acceptance.md)，第二轮见 [acceptance-v2.md](acceptance-v2.md)，第三轮单独采证，不将设计目标直接当作通过事实。

## 现状与原因

第三轮微调已由用户直接提出并授权。当前目标覆盖此前“下方四按钮及说明”的约定：移除图样下方文字、计数、横线和选图按钮，仅保留 44px 点击区域内的小型暂停/播放图标。画布外层使用透明、无可见边框的原生按钮，点击/轻点切换下一幕，Enter/Space 沿用原生点击，左右方向键与 Home/End 直接选图；暂停/reduce 时仍可手动选静态幕，画布外不注册快捷键。故障时画布按钮禁用。

金色翼尖的下沿从原 SVG 下翼上边界 Bézier 曲线尾段直接采样，接缝共用坐标和深度，边缘增加采样权重；只调整粒子几何，不修改原 SVG/词标。投影比例从 .55 增至 .61，画布纵横比从 1.12 改为 1，桌面图样线性尺寸约增加 24%；窄屏占位由 300px 上限提高到 340px（中间断点上限 380px），仍保留预算与数值/视觉边界检查。

第三轮后续贴合修正（Type B）：用户指出金标左上角仍伸出白翼。上角改取白色上翼内侧曲线的连接点，上沿复用该曲线尾段，向内收至双翼包围的轮廓内；下沿接缝及图样大小沿用第三轮。验证时同时核对上下接缝及金色点是否越过双翼外轮廓，另存第四版局部修正证据。

第三轮采证发现同一 IntersectionObserver 通知可包含先离屏、后可见的多条记录；控制器读取最后一条，避免停在过时状态。此处沿用原有可见恢复契约，补充两个方向的批次顺序回归，不增加第二条调度链。

正式入口为 AuthLayout.vue，右侧 LoginParticleScene.vue 挂载 loginParticleMotion.ts，几何来自 loginParticleGeometry.ts。第一轮的 morphPoint 在相邻模型线性插值后，对 x/y/z 分别加均匀随机数；x/y 最大偏移约 0.725 装饰单位。这个规则容易把形状外扩为矩形范围，投影靠近画布边缘时更明显。当时左侧标题是固定 DOM，与连续进度没有联系；第二轮已替换这些行为。

第二轮仍保留同一套控制器和生命周期约定，只扩展几何、变形、进度输出和介绍文字。三份模型变为四份，连续进度从 [0, 2] 扩展至 [0, 3]，上下界、计数、选图、测试页和测试共同使用场景数量，不散落魔法数字。

## 四幕图样与中文文案

斜线表示明确换行，不在产品中显示斜线。四组标题都为两行，每行不超过五个汉字；说明为一句正常 DOM 文字。

| 章节 | 粒子图样 | 左侧标题 | 说明 |
| --- | --- | --- | --- |
| 01 品牌标志 | 现有双翼 Logo；主色描出翼面，强调色集中在翼尖，轻微呼吸。 | 让每个回答 / 都有出处 | 连接知识与问题，让回答有据可循。 |
| 02 知识文档 | 保留叠放书页、折角和短行纹理。 | 把分散资料 / 变成知识 | 将资料整理进知识库，为检索与问答做好准备。 |
| 03 检索关联 | 保留中心节点、邻近节点与关联线。 | 沿着问题 / 找到线索 | 从知识库中检索与问题相关的内容。 |
| 04 引用回答 | 保留回答卡片、文字行和来源标记。 | 答案有依据 / 来源可核对 | 结合检索内容组织回答，并提供可核对的引用。 |

文案解释产品用途，不增加准确率、全量覆盖、速度或生产规模承诺。开场沿用当前主标题，建立熟悉感，再用后续章节解释它的含义。

Logo 从现有词标及 login-logo.svg 的三条双翼路径核对轮廓；按原有 Bézier 曲线做确定性轮廓/翼面采样，不改变原始 SVG。翼尖保留强调色，厚度克制，避免变成另一种飞鸟或纸飞机图标。采样在模型初始化时完成，不逐帧解析路径。

## 轮廓散开与聚合

### 形态路径

1. 离开完整图样时，细节先松开，外部轮廓仍能被看见。
2. 过渡中段让点位在两幅图样的轮廓邻域之间移动；通过平滑插值逐步转向下一图样，保留少量外围游离点，不均匀铺满矩形区域。
3. 接近完整图样时，外围点逐渐归位，轮廓先清楚、细节随后收紧。两端偏移严格为零，完整模型与选图端点一致。实际调参采用前 72% 进度完成轮廓插值，再收紧散开；文案共用这一插值曲线，使中间态以目标图样和文字为主，避免等亮叠字及点云过度收缩为中心团。

每粒子保留稳定对应关系与随机种子。相邻图样使用一条由连续进度决定的可逆路径，中途反向沿当前路径退回，不因滚动方向改变而重新抽随机点或突然换锚点。“下一图样周围”通过逐步偏向目标轮廓实现，不在半程硬切到另一幅模型。

### 计算约束

- 以插值后的轮廓点为锚，结合局部切向与由模型中心指向点位的径向计算偏移；中心附近用固定种子生成备用方向，避免除零。
- 随机半径采用中心更密、外围更稀且有界的连续分布，角度均匀。偏移方向不能由 x/y 两个独立均匀数拼成方形；不把当前方云仅裁成圆形遮罩。
- 散开包络两端为零，中段最大；最大位移初始目标约为当前图样短边的 10%～18%，通过实际中间态截图在预算内调整。可保留很轻的切向弧线与纵深，避免强旋涡掩盖轮廓。
- 投影统一预留约 10% 的边缘空间，计算时考虑宽高比、最大散开、呼吸、旋转和已有鼠标偏移上限。采用稳定缩放，不逐帧按极值自动放大缩小。
- 对 0.25、0.5、0.75 等阶段检查点云包围范围和边缘密度；数值边界只证明没有截断，仍须视觉判断有无方块感。

不增加粒子总量：桌面最多 4800、CSS 宽度小于 360px 时最多 2000；DPR≤1.5、最长边≤1200 设备像素，连续绘制目标上限 30 fps。额外随机方向可初始化预计算，避免逐帧分配。

## 文案同步与表单稳定

控制器把实际平滑进度提供给组件，再由组件向 AuthLayout 输出同一进度及 renderer/paused/reduced 状态。文字必须使用实际画面进度，不能使用目标索引另起一个定时器；只保留原有一条 RAF 调度链。销毁后的进度回调受同一挂载标记保护。

相邻两幕标题和说明按进度交叉淡化，附加约 12～18 CSS px 的垂直位移。使用局部归一化权重，保证不会两幕同时完全消失，也不让多幕正文堆在一起。非相邻章节选择仍沿同一进度路径经过中间章节。

文案区用叠放层及每断点下最长文案所需空间预留高度；标题两行、说明允许窄屏换行，切换不改变表单起点。只动画 opacity/transform，不重建 router-view/LoginView、不重挂输入框、不移动焦点、不清空输入、不动画表单。

可访问名称始终只有一份当前标题和说明；视觉过渡层 aria-hidden，不逐帧通过 aria-live 朗读。最近章节在实际进度越过半程时更新图样按钮的可访问名称，键盘焦点保持在用户操作位置。

- 暂停：粒子与文字一起落到最近完整章节，手动选图同时更新完整画面和文案。
- reduce：不做文字淡入/位移或连续变形，选图直接更新静态画面及对应文字。
- 隐藏/离屏：停止绘制和进度输出，不补播；恢复时文字与同一画面进度一致。
- 渲染故障：显示既有品牌 SVG，并回到品牌章节文案；禁用无效选图，恢复成功时按控制器实际状态同步，避免 Logo 配上“引用回答”的错位。

## 交互与资源约定

首次进入为品牌完整图样，仅轻微环境呼吸，不自动轮播。进度为 [0, 3]，保留 canvas 局部滚轮、deltaMode 归一化与单事件步长限制。Ctrl/Meta、横向主导、不可取消、画布外、端点向外、暂停/reduce/故障事件继续放行，不在页面或表单注册全局滚轮。

图样自身为原生 type=button，Tab 可达，点击/轻点/Enter/Space 循环下一幕；左右键在首尾限位，Home/End 到达首尾幕。快捷键仅在图样上生效，带 Ctrl/Meta/Alt 的操作放行。暂停图标保持独立可达，点击区域为 44 CSS px；触屏保留纵向滚动和双指缩放，不增加拖动手势。

鼠标刷动半径、有限偏移与阻尼恢复保留。单 RAF、主题刷新、reduce、隐藏/离屏、WebGL 故障/恢复、部分初始化清理及幂等销毁沿用首轮约定，新增文案回调也不能在销毁后更新状态。组件不接触凭据、业务数据或 auth store。

## 实施范围与验收

预计生产修改为 AuthLayout.vue、LoginParticleScene.vue、loginParticleGeometry.ts、loginParticleMotion.ts；测试修改为 login-particle.test.mjs 与 particle-checks.html，若共享章节定义需要独立模块，限定于登录装饰工具目录。LoginView、旧双翼实现、原始 SVG、独立原型、主题 store、路由及依赖文件保持原样。

几何测试覆盖四模型等长/有限数、Logo 路径一致性、四端点、三段确定性及双向连续、径向散开和投影边界。组件测试覆盖实际进度同步、暂停/reduce/故障同幕、表单不重挂和迟到回调；继续运行原有资源/事件保护测试。

浏览器检查深浅主题的 1440×900、1024×768、390×844。桌面两主题各检查四个完整场景；三段过渡均检查 25%/50%/75% 并各保留中间态截图，针对齐平边缘、角部积点和裁切作视觉判断。检查金白接缝、放大比例、下方仅留暂停图标，以及反向滚动、鼠标扰动、键盘/触屏替代和窄屏标题换行。先填入合成用户名/密码，再切换，确认内容和表单坐标不变；用 DOM 状态检查控件未被重建，图样按钮取得焦点属于正常操作，不要求焦点自动返回输入框。

运行前端聚焦/全量回归、含 vue-tsc 的正式 FrontendBuild、DocAndScope 与范围检查。真实业务调用仍为 0。首轮 evidence 清单和截图保留原样；第二轮使用独立证据文件与截图目录，并记录源码哈希。正式接受仍需用户视觉审阅，实体设备和硬件长稳不以桌面模拟代替。

## 决策记录

第三轮取舍：用户明确要求只留暂停图标，因此用图样自身的原生按钮语义保留点击/触屏/键盘替代操作，不再显示选图控件。扩大尺寸采用固定比例及占位调整；边界测试继续计入散开、鼠标偏移和旋转，避免用裁切换取视觉放大。既有章节文案、表单和生命周期约定沿用。

### D1–D4：沿用首轮已确认的技术路线

继续使用原创原生 WebGL1、局部滚轮加按钮、统一细点及故障 SVG 回退；保留旧双翼实现。第二轮扩展为四章节，但不引入依赖、全页滚动接管或真实业务调用。首轮取舍和已完成证据由原提交及验收记录保留。

### D5：用现有品牌轮廓开场

直接使用现有双翼的几何轮廓，避免用户进入登录页后先看到一个陌生标志。可重新设计品牌或只用 RAG 字样，但前者扩大本轮范围，后者需要处理字形和字体依赖；本轮都不采用。

### D6：从轮廓附近散开，而不是扩大随机方云

- **当时面临哪几个选择？** 可以仅缩小随机幅度，可以给画布套圆形遮罩，也可以改为轮廓锚定的有界径向/切向散开并预留投影空间。
- **最终选了谁与理由是什么？** 选择第三种。方形分布的生成规则得到改变，中间态仍能透露正在出现的图样；边缘留白同时减少裁切。
- **其他方案的代价是什么？** 缩小幅度最简单，但残留方形分布；遮罩容易把问题变成圆形裁边，不能解决点位怎样聚集。新方案需要增加三段中间态及反向连续检查。

### D7：让介绍文字共享粒子进度，表单独立稳定

- **当时面临哪几个选择？** 可以只按按钮切文字，可以给整块左侧做轮播，也可以只让标题/说明跟随粒子的实际连续进度。
- **最终选了谁与理由是什么？** 选择第三种。滚轮和按钮两条路径都能保持图文一致，表单不会随故事退出画面。
- **其他方案的代价是什么？** 按按钮切文字覆盖不了滚轮中间态；整块轮播会影响输入、焦点和布局。独立文案层需要预留高度并处理可访问文本，但范围可控。
