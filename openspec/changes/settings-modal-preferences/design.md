# 设置浮层与偏好接入设计

## 💡 30秒人话设计主旨

保留原设置浮层，让用户调整阅读和操作方式。选择立即生效，能保存就刷新沿用，不能保存也可本次使用并看到提示；设置不会重发问题，也不会让未完成的流式回答获得来源。

## 首版范围

实现[已批准规划](../../../docs/01-规划与调研/设置浮层扩展-设计规划.md)五类栏目及默认值。桌面最大 960 px、左导航 190 px，标题固定、内容滚动；45rem 以下使用统一分类选择控件，同一 dialog 无新路由。极矮视口保持关闭和最后操作可达。使用现有 tokens、字体与 Lucide。下拉框按用户追加反馈采用 D6。

theme store 保留原 theme 键及 system/light/dark 兼容。新增 preferences store，挂载前初始化，用 rag.ui.preferences.v1 保存 `{version:1, answerTextSize:small/standard/large, motion:system/reduce, sendKey:enter/modifier-enter, sources:collapsed/expanded}`。字段独立校验，坏 JSON/未知版本回默认；只存白名单枚举。存储失败保留内存选择，theme 与 preferences 独立记录故障。其他标签刷新读取，不实时同步。

字号用根 CSS 变量只作用 AnswerContent 正文/相对标题/表格，标准沿用 15 px，代码/输入/导航不变。系统减少或本地 reduce 任一生效就减少。store 管理系统监听，粒子接受有效信号及订阅，旧独立调用保留原系统默认；卸载清理，避免双监听。CSS 减少不必要位移与循环动画，状态文字仍可读。

发送键纯函数检查 Enter/修饰键/Shift、repeat、isComposing/keyCode=229 和组合结束边界，再调用原 handleSend，保留请求中保护。来源创建时快照偏好，用 details 保留人工 toggle；不改 ChatPanel 来源条件，不因设置变化重置已挂载卡片。

账户复用 auth/context，不新增资料请求；退出复用 useAuth 并共享进行中状态，沿用 confirmed/unconfirmed/superseded 提示。历史入口正常点击先关闭再导航，保留原生新标签行为。Vite 从 package.json 注入真实前端版本，不联网、不暴露本地路径。

## 浮层与重置生命周期

general/security/apiKey→appearance，profile→account。打开记录焦点、锁背景，关闭/卸载仅释放持有的 overflow/inert。焦点循环覆盖当前可见可用 button/a/input/select；radio 组按原生 Tab 规则。关闭回触发器，消失或隐藏则回移动侧栏入口；退出服从登录流程。分类切换内容归顶。

数据栏目行内确认重置，焦点进入取消。Escape 先取消再关闭。确认把 theme 置 system、四项置默认，仅写两个自有 key，不清存储、凭据或业务。任一保存失败明确提示刷新可能恢复旧值。打开/关闭设置与偏好变化不得卸载业务页、重连 SSE、重发 ask 或清草稿。

## 验证与回滚

采用现有 Vite SSR 测试与封闭预览覆盖存储、IME、来源、动效、锁；全量前端、正式 build、DocAndScope/SensitiveLogs。浏览器拒绝外部来源，合成接口观测计数/终态，不冒充真实设备/业务证据。回滚只定向移除本 change 接线，theme 保持旧值兼容，未知偏好降级，不改业务资料。

## 决策记录

### D1：保留浮层
用户明确选择沿用。nav/button 与窄屏 select 保持原入口和业务页，独立路由会增加草稿/返回生命周期处理，本轮不需要。

### D2：本地即时保存
- **当时面临哪几个选择？** 统一保存、即时本地保存，或后端云同步。
- **最终选了谁及理由？** 选本地即时，变化立即可见，存储失败仍可本次使用。
- **其他方案的代价是什么？** 总保存需要关闭撤销；云同步需要新接口。本地方案跨账号共用且不跨设备，界面明确说明。

### D3：系统减少优先与监听归属
- **当时面临哪几个选择？** 粒子和偏好各监听系统，或应用共用一个有效信号。
- **最终选了谁及理由？** 共用信号，系统减少优先，粒子注入订阅并保留旧独立调用默认。
- **其他方案的代价是什么？** 双监听容易接入但有冲突/清理风险；注入需要补生命周期回归。

### D4：保留问答契约
仅改阅读和发送操作，保留同步默认、显式流式、ANSWER 终态、历史只读及请求参数。模型/检索/流式默认会改变业务与基线，不纳入。

### D5：行内重置与真实资料
单层 modal 内确认，复用账户/退出来源，限定重置副作用；暂不增加历史删除、编辑账户或组织切换。

### D6：统一设置下拉框的展开样式

2026-10-27 用户根据实际截图要求下拉框更加现代，授权替换首版原生 select 的呈现。复用现有 Element Plus ElSelect，不新增依赖；五处选择统一为圆角触发区、浮起的菜单、悬停底色与显式勾号。数据、默认值、保存与业务行为不变。菜单挂到当前 dialog 内，保留背景 inert 和焦点边界，按浮层可用空间换向/限高；Escape 先关菜单，再关闭设置，Tab 不离开设置。

候选方案是继续使用操作系统菜单、自己实现 listbox，或复用已有组件。选择复用能统一展开样式并沿用组件已有的方向键/Home/End/Enter 操作；原生菜单难以控制截图中的系统选中条，自研则增加焦点与定位维护成本。本次仅覆盖设置内选择，不替换聊天页或知识库控件。
