# 设置浮层与本地偏好：实施记录

> 日期：2026-10-27。状态：`REVIEW_READY · 待用户审阅`。比较锚点为 Git HEAD `15ca6b1`，实现仍在工作区中，未提交；源码与审阅工件指纹见 [manifest](evidence/manifest.json)。

## 💡 30秒人话导读

设置现在能真正调整阅读和操作方式：用户可以切主题、放大回答、减少动画、选择发送键，以及决定新来源卡是否展开。选择即时生效并保存到当前浏览器；保存失败会说明限制，重置只恢复自己的偏好。账户继续显示真实上下文，生成中的回答、草稿和来源终态规则保持原样。

## 实际改动

涉及 16 份前端生产/配置文件和 7 份测试/浏览器脚本，不改后端、依赖、数据库、真实配置或 baseline。五类设置、旧入口映射、窄屏分类、焦点与行内重置已接入；系统减少动效优先，应用卸载时清理两个偏好监听。退出显示共享进行中状态，仍复用原 useAuth 单次请求与身份保护。

默认值为主题 system、回答字号 standard/15 px、动效 system、发送键 enter、来源 collapsed。新偏好只写 rag.ui.preferences.v1 的固定枚举；theme 保持旧键。字号只影响回答正文/相对标题和表格，代码/输入/导航尺寸不变。来源初始状态是快照，设置变更不覆盖已挂载卡片的人工操作。输入法组合、组合结束短边界与重复键不会误发。

使用 better-layout、better-accessibility，以及收尾对比度检查中的 better-colors 规则。新增语义 token --rag-border-control 供设置控件使用，避免借用浅色占位文字的较弱边界色；没有改整个主题色系。

## 首轮失败与修正

首轮正式构建发现重复导入，修正后正式构建通过；旧 SSR 设置夹具只替代侧栏的依赖，扩展为同样隔离设置组件后通过。新增粒子回归去除重复测试名，最终总数为 143，不把重复用例计为新覆盖。

浏览器脚本初次遇到抽屉时序、固定用户名在资料失败时不存在、错误的同步来源场景、已登录访问登录页被原 guard 返回，以及完整 radio 命中层使文字定位器误判拦截。均按已有界面事实修正测试等待/场景/定位，保留实际指针点击；没有通过放宽业务断言或改生产权限让测试通过。
